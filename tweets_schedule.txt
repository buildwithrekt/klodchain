## SEMAINE 4 - Educational Content

24. ELI5 Proof of History: Imagine a clock that everyone agrees on, but no one can cheat. That's PoH. It orders transactions before consensus.

25. Why does Solana need validators? They're like notaries. They verify transactions are legit and agree on the order. Consensus in action.

26. Lamports are to SOL what cents are to dollars. 1 SOL = 1,000,000,000 lamports. Named after Leslie Lamport, distributed systems legend.

27. Slots vs Blocks: A slot is a time window (~400ms). A block is what a validator produces in that slot. No block = skipped slot.

28. The System Program (address: all 1s) is Solana's built-in program for basic operations. Every chain needs primitives.

29. Rent on Solana: Accounts must maintain a minimum balance or get purged. It's like storage fees for the blockchain state.

30. Transaction fees on Solana are fixed at 5000 lamports (~$0.00025). Priority fees let you jump the queue during congestion.

31. What's a blockhash? A unique identifier for each block. Transactions reference recent blockhashes to prevent replay attacks.

## SEMAINE 6 - Tips & Insights

40. Tip: Want to understand any system? Build a simplified version. You'll learn more than reading 100 articles.

41. Supabase + Next.js is perfect for real-time apps. Blocks stream instantly with zero configuration. Highly recommend this stack.

42. Debugging distributed systems is hard because you can't step through code across multiple nodes. Simulators help visualize the flow.

43. TypeScript tip: Use branded types for pubkeys and signatures. Prevents mixing up strings that look the same but mean different things.

44. Performance insight: Batching database writes is crucial when producing blocks every 400ms. Learned this the hard way.

45. React tip: Use `useTransition` for non-urgent updates. Keeps the UI responsive when blocks flood in at 10x speed.

46. The best architecture is the one you understand. I simplified Solana's internals for education, not production accuracy.
